# Разработка модуля SoundCloud без готового интерфейса

## Что уже есть

- crates/soundcloud/src/lib.rs — библиотека с SoundCloudClient, Track, SearchResults и ResolvedStream.
- crates/soundcloud/src/main.rs — консольная команда soundcloud-probe, использующая ту же библиотеку.
- scripts/check-soundcloud.ps1 — запуск на Windows x64 с автоматической подготовкой yt-dlp.
- scripts/setup-ytdlp.ps1 — загрузка закреплённого официального выпуска и проверка его SHA-256.

Отдельный веб-сервер не нужен. Rust-модуль работает локально и запускает yt-dlp как дочерний процесс. Вызовы выполняются без shell; пользовательский запрос передаётся отдельным аргументом. Установленная конфигурация yt-dlp, плагины и файловый кэш отключены для воспроизводимой проверки без заранее настроенных ключей и cookies.

## Как проверять свою часть

### Поиск

Из корня репозитория:

```powershell
.\scripts\check-soundcloud.ps1 -Query 'lofi hip hop' -Limit 5
.\scripts\check-soundcloud.ps1 -Query 'Молчат Дома' -Limit 3
```

Успешный ответ — JSON с query и tracks. У каждого трека есть id, title и webpage_url. Поля uploader, duration_seconds и artwork_url могут отсутствовать и возвращаться как null. uploader означает автора загрузки, который не всегда совпадает с исполнителем.

Поиск требует действующего интернет-подключения. Нулевое количество совпадений допустимо. Нельзя проверять интеграцию по точному порядку результатов: выдача сервиса меняется.

### Получение потока

Возьмите webpage_url одного из результатов и выполните:

```powershell
.\scripts\check-soundcloud.ps1 -Mode resolve -Query 'https://soundcloud.com/hephestosmusic/super-mario-world-game-over'
```

Успех — JSON с track, url и данными формата. Адрес url временный, его нужно получать перед проигрыванием. Это проверка получения потока; само воспроизведение аудиодвижком выполняется отдельно.

Некоторые найденные записи доступны только как превью либо недоступны для воспроизведения. Ошибка такой записи не означает, что весь поиск сломан.

### Проверки без SoundCloud

```text
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all --check
```

Тесты не обращаются к сети. Они проверяют отсутствие необязательных метаданных, обложки в формате плоской выдачи, отклонение поддельных доменов и невалидных входных данных. Успешные тесты не заменяют реальный поисковый запрос.

## Linux x86_64

На Linux необходимы Rust stable и системные инструменты компиляции. Самостоятельный yt-dlp не требует отдельной установки Python:

```bash
mkdir -p tools
curl --fail --location --output tools/yt-dlp_linux https://github.com/yt-dlp/yt-dlp/releases/download/2026.10.26/yt-dlp_linux
printf '%s  %s\n' '767ba9dce7052aa196f8b12652f433d76de128ba168966fa84b6394d5e6c6795' 'tools/yt-dlp_linux' | sha256sum --check
# Продолжайте только при успешной проверке SHA-256.
chmod +x tools/yt-dlp_linux
cargo run --locked -p fuzzy-soundcloud --bin soundcloud-probe -- search 'lofi hip hop' --limit 5 --yt-dlp ./tools/yt-dlp_linux
```

Эта инструкция предназначена для x86_64; Linux-проверка ещё не выполнена. На других архитектурах нужен соответствующий бинарник.

## Подключение будущего интерфейса

Rust-код Tauri сможет использовать библиотеку fuzzy-soundcloud по локальному пути и вызывать:

- SoundCloudClient::search(query, limit) — поиск;
- SoundCloudClient::resolve(track_url) — получение доступного потока.

Вызовы синхронные: в Tauri их нужно выполнять вне потока интерфейса. Общий тайм-аут и программная отмена уже реализованы. Интерфейс получает модели данных и состояния загрузки/ошибки; получение потока остаётся в Rust.

### Тайм-аут и отмена

Обычные search и resolve используют RequestOptions по умолчанию: 45 секунд и отдельный CancellationToken на вызов. Для управления запросом вызывайте search_with_options или resolve_with_options.

RequestOptions содержит timeout (std::time::Duration) и cancellation (CancellationToken). Сохраните клон токена перед запуском работы в фоновом потоке. При новом запросе или нажатии кнопки отмены вызовите cancel() на этом клоне. Для следующего запроса создайте новый токен: отменённый токен остаётся отменённым.

Ограничение действует от начала запуска извлекателя до завершения процесса и чтения его вывода. Сетевой тайм-аут yt-dlp в 15 секунд сохраняется отдельно. Подготовка инструментов и компиляция Cargo происходят до этого ограничения. Проверка отмены выполняется примерно раз в 20 мс; точное время зависит от планировщика и завершения процессов ОС.

Процесс запускается в группе процессов на Unix и Job Object на Windows. На отмене, тайм-ауте или ошибке ввода-вывода группа завершается и дочерний процесс освобождается. stdout и stderr читаются параллельно: большой вывод в одном канале не блокирует другой. Вывод ограничен 8 МиБ для stdout и 1 МиБ для stderr.

API возвращает SoundCloudError с вариантами InvalidInput, Cancelled, TimedOut, Process, ExtractorFailed и InvalidResponse. Логика интерфейса может сопоставлять варианты, не анализируя текст сообщений. Ошибки, сообщённые самим yt-dlp (включая сетевые и ограничения сервиса), пока объединены в ExtractorFailed: их подробная классификация остаётся отдельной задачей.

Для проверки без приложения:

```powershell
.\scripts\check-soundcloud.ps1 -Query 'lofi hip hop' -TimeoutSeconds 1
.\scripts\check-soundcloud.ps1 -Query 'lofi hip hop' -CancelAfterSeconds 0.25
```

Оба примера обычно завершаются ошибкой timed out/cancelled с кодом 1. Если запрос успел закончиться раньше заданного ограничения, возвращается успешный результат. Параметр CancelAfterSeconds демонстрирует программную отмену и не является обработчиком Ctrl+C.

Автотесты без сети запускают настоящий тестовый процесс, проверяют тайм-аут зависания, отмену до запуска, параллельное чтение большого stdout/stderr и остановку дочернего процесса по отмене. Игнорируемый child_fixture — служебный процесс, который тесты запускают явно.

## Что разрабатывать дальше

1. Подключить RequestOptions и CancellationToken к фоновым командам Tauri, когда появится каркас приложения.
2. Разделить ошибки сети, недоступной записи, ограничения запросов и повреждённого ответа на отдельные типы.
3. Измерить и сократить задержку поиска; добавить безопасное повторное использование автоматически найденного идентификатора и кэш результатов.
4. Определить способ продолжения поисковой выдачи.
5. После согласования контракта подключить модуль к Tauri и аудиодвижку.

## Подтверждённый результат прототипа

16 ноября 2026 на Windows с Rust/Cargo 1.100.0 и yt-dlp 2026.10.26:

- Поиск lofi hip hop вернул 5 результатов примерно за 10 секунд.
- Поиск Молчат Дома вернул 3 результата с обложками.
- Для публичного трека получен поток hls_aac_160k, прочитан HLS-медиаплейлист и первые 1024 байта аудио.
- Полная композиция не скачивалась; звук не запускался.

Проверка не гарантирует доступность всего каталога или постоянную работоспособность внутреннего интерфейса SoundCloud. Упаковка готового плеера и воспроизведение на обеих ОС требуют отдельных проверок.

## Работа с Git

Одна законченная задача — отдельная ветка и небольшие осмысленные коммиты. В Pull Request нужно указать, что изменилось, и привести команды проверки. В main изменения попадают после проверки вторым участником.

Папки tools, target и work, аудиофайлы и учётные данные в коммит не включаются. Первоначальная настройка и тестовые скрипты не публикуют ничего в GitHub.
