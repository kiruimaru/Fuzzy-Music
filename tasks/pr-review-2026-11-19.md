## Findings: PR #23

### P1: The advertised four-track audio bound is not enforced globally

`src-tauri/src/lib.rs:497` warms only three neighbours in each cycle, but
`src-tauri/src/audio_cache.rs:280` evicts only at 41 entries. Neither manual
selection nor a new neighbourhood removes old audio. Signed entries can remain
for 55 minutes. Moving through a playlist therefore accumulates old warm tracks.

Reproduction: warm eight successive keys with three 1 MiB segments each, using
a local signed HLS fixture. Actual retained payload: eight tracks / 24 MiB;
the current-plus-three assertion fails. The code permits 123 MiB of retained
audio payload, plus manifests, transfers, runtime allocations and mpv.

The latest fix reduces work per cycle; it does not implement the stated
approximately 12 MiB global audio budget. This is excessive bounded retention;
an unlimited retained-cache leak or whole-machine OOM was not demonstrated.

Required: enforce a global byte/entry budget and evict outside the current
warm neighbourhood, preserving resources still being read by playback.
Keep the larger link-metadata cache independent of the audio budget.

### P1: Manual Play starts unlimited, untracked audio workers

`src-tauri/src/lib.rs:329` spawns a new thread for every Play cache miss via
`warm_at`. These workers bypass the eight-worker lookahead pool and use no
selection cancellation token, in-flight deduplication or `Active` ownership.
An unfinished warm is still a cache miss, including repeated selections of the
same track. The epoch prevents old publication after Stop, but does not stop
an in-flight HTTP request or wait for its worker.

Reproduction: preload twelve stream links, switch through them against a slow
local HLS fixture, and observe twelve concurrent manifest downloads. The global
eight-worker assertion fails. Retained cache caps do not bound these transient
allocations, threads or network requests.

Required: put manual and speculative warming through one bounded scheduler,
deduplicate in-flight keys, cancel obsolete work and account for shutdown.

### P2: HTTP cancellation cannot interrupt in-flight requests

`crates/soundcloud/src/web.rs:59` checks cancellation only before and after
blocking HTTP/body reads. Production track search now uses this transport;
shell tests select the old extractor path with `cfg(test)` and miss the change.
Replacement searches leave old calls running, and shell shutdown waits for
their `Active` guards. A stalled request can delay close by the default 45s.

Reproduction: cancel at 50ms against an 800ms local response. Cancellation is
reported only at approximately 805ms, failing the 300ms responsiveness check.

Required: cancellation-aware transport and tests exercising the production
search path, including replacement and closing during a stalled response.

### P2: The request timeout resets for every HTTP request

`crates/soundcloud/src/web.rs:45` configures the full `RequestOptions.timeout`
per request, and `:61` resets timing inside each GET. Client-id discovery,
refresh, playlist resolution and stub batches have no shared deadline.
Discovery also continues after failed script downloads. One operation can take
many multiples of the documented timeout.

Reproduction: two 150ms GETs both succeed in approximately 308ms with a 250ms
operation budget. The operation-deadline assertion fails.

Required: one absolute operation deadline; pass its remaining duration into
each request/body read and propagate timeout rather than continuing discovery.

## Findings: PR #20

### P1: Windows packaging changes break Linux release tool discovery

`src-tauri/src/dependencies.rs:13` requires executable-relative tools for every
release build, including Linux. A normal Linux setup with yt-dlp/mpv installed
on PATH now chooses absent `tools/yt-dlp` and `tools/mpv` instead. The new
bootstrap supplies only Windows tools; the existing Linux setup is not migrated.
The decision records the new convention, but that does not provision Linux tools.

Reproduction: compile the discovery helper with `--edition=2024
-C debug-assertions=no`, with real `/usr/bin/mpv` on PATH and no tools beside the
test executable. The helper returns a nonexistent executable-relative tools path.

Required: scope mandatory portable discovery to Windows, or provide and verify
the Linux packaging/setup migration in the same change. Explicit FUZZY overrides
remain a workaround, not compatibility with the previous normal setup.

### P2: Missing-extractor repair instructions are discarded by the UI

`crates/application/src/lib.rs:86` adds the setup command to the safe error,
but `src/api.ts:42` replaces it with the old generic source-unavailable text.
A fresh portable user with no runtime receives no actionable setup instruction
through the search error. The new Rust test only verifies the DTO message.

Reproduction: reject search with the new missing-extractor DTO and inspect the
rendered error. It contains no `setup-windows-runtime.ps1`; the UI assertion fails.

Required: a safe structured distinction for missing runtime and corresponding
UI guidance; continue rejecting arbitrary external diagnostics.
